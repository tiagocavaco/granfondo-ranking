# Spec — localisation (pt-PT default, en)

Status: proposed. Promotes frontend plan 4.7 from "later" to Milestone 2:
the audience is Portuguese, the UI is English, and every organiser and
sponsor conversation will be in Portuguese. Also covers the backoffice
(English only, no change) and the share cards.

## 1. Decisions

| Question | Decision | Why |
|----------|----------|-----|
| Default locale | `pt-PT` | Audience; SEO for Portuguese queries |
| Second locale | `en` | Foreign riders (15% of results are non-PT), organisers' sponsors |
| Locale in URL? | No. `<html lang>` + a toggle; stored in `localStorage`, initial from `navigator.languages` | Keeps every existing link valid; the site has one canonical URL per page |
| Library | `i18next` + `react-i18next` with JSON resources, or a 60-line `t()` over a typed key map | Either; prefer the small custom one unless plurals/ICU are needed. Recommendation: `i18next` with `i18next-icu` off, plural rules via its built-in `_one/_other` keys |
| Key style | Namespaced flat keys: `events.hero.nextRace`, `ranking.table.points` | Greppable, stable across redesigns |
| Fallback | `en` for missing `pt` keys, and a dev-only console warning | Never render a raw key |

## 2. Scope of strings

Counted on the current frontend with a naive grep: 35 multi-word JSX text
nodes, 11 placeholder/label/title attributes and 11 hard-coded `en-GB` date
formats. The grep misses text split across lines, template strings and
single words, so the real extraction will find more; budget for 150–250
keys plus the three info pages (prose). Not translated: athlete, team and event names;
raw category strings (see §4).

## 3. Formatting

- Dates: `Intl.DateTimeFormat(locale, …)` through one helper `formatDate(date, style: "full" | "short" | "monthDay")`; delete every `toLocaleDateString("en-GB", …)`.
- Numbers: `Intl.NumberFormat(locale)` for finisher counts and points (pt uses a space or dot as thousands separator; keep points at one decimal).
- Times and gaps stay `HH:MM:SS`.
- Relative age ("updated 6 days ago"): `Intl.RelativeTimeFormat`.

## 4. Categories and distances

- Distances: canonical names are the same word in both languages; no translation.
- Categories: display `canonicalizeCategory(raw)` through a label map per locale (`Masters B Male` → pt `Masters B Masculino` / en unchanged); the raw source string is shown only in the backoffice. This also closes frontend issue B8.
- Gender labels, status chips ("Upcoming", "Results pending"), rank words ("pts", "races") all through `t()`.

## 5. Where the text lives

```
frontend/src/i18n/
  index.ts          init, locale detection, toggle, useT()
  pt.json           default
  en.json
  format.ts         formatDate, formatNumber, formatRelative
```

Info pages (`ranking-info`, `teams-info`, `predictions-info`) are prose:
store as Markdown per locale under `frontend/src/content/<locale>/` and
render with a minimal Markdown component, rather than as JSON keys.

## 6. SEO and sharing

- `<html lang>` follows the locale; `<title>` and meta description per page per locale.
- `hreflang` is not needed without locale URLs; a single canonical per page.
- Share cards render in the viewer's locale at request time (backend spec) or in `pt` when generated at build.

## 7. Backoffice and docs

Backoffice stays English (operator tool). The organiser offer already
exists in Portuguese (`docs/monetization/04-organiser-offer.pt.md`); legal
pages exist in both (`docs/legal/`).

## 8. Migration steps

1. Add the i18n module with `en.json` extracted from the current strings (a codemod that replaces string literals in JSX with `t("…")` keys, reviewed by hand).
2. Add `pt.json`; native review of tone (informal "tu" vs formal "você": use impersonal phrasing to avoid the choice, e.g. "Pesquisar atleta" not "Pesquise").
3. Replace date/number formatting with `format.ts`.
4. Category label map.
5. Locale toggle in the footer and the mobile tab bar's search sheet.
6. Playwright: one smoke run per locale asserting no raw keys (`/[a-z]+\.[a-z]+\.[a-z]+/` pattern absent from body text) and correct `lang`.

## 9. Acceptance

- Zero user-visible string literals in `frontend/src/components/**` (lint rule: `react/jsx-no-literals` with an allowlist for symbols and numbers).
- First visit from a `pt` browser is entirely Portuguese, including dates.
- Toggling locale changes text, dates and category labels without reload.
